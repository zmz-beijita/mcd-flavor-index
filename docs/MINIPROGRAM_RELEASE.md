# 微信小程序发布指南

> 麦门真香榜 · 微信小程序版 · 2026-10-25

## 先说清楚两件事

**1. 本项目当前发布到哪里了？**

已创建的是 **WorkBuddy 的小程序应用卡**（应用列表里那个「麦门真香榜」，
内部 id `wbapp_4KmyljumDI0OOe6djGVt6j`）。
它**不是微信小程序** —— 不会出现在微信搜索里，也不在微信的小程序列表中，
它是 WorkBuddy 内部的预览 / 分享载体。

**2. 上架微信要做两件事，不是一件**

| # | 事情 | 谁做 | 耗时 |
|---|---|---|---|
| ① | **注册小程序账号**（拿 AppID） | 你 | 当日可完成，**免费** |
| ② | **提交版本审核** | 你 | 代码审核 24–48 小时；**但备案终审 3–20 个工作日** |

> ⚠️ **时间预期要说实话**：代码审核不算久，但 2026 年起小程序发布前还需要
> **工信部备案**（平台初审 1–2 个工作日 + 管局终审 3–20 个工作日，
> 北京地区通常更严）。**备案是硬门槛，无法跳过。**
>
> 也就是说：**今晚（定榜日）上架微信不现实**，
> 但**注册今天就能做完**，AppID 拿到后其余环节都能提前准备。

## 路线 B 的第 ① 步：注册账号（今天就能做完，免费）

个人主体注册**免费**（不用 300 元认证费 —— 那是企业主体才有的年审费）。

**要准备的三样东西**：
1. **一个没用过微信公众平台的邮箱**（公众号 / 小程序 / 企业微信都不能用过）
2. **本人身份证**（用于实名认证，信息要和微信实名一致）
3. **一个已实名、绑了银行卡的微信号**（当管理员，收审核通知）

**操作**：
1. 打开 https://mp.weixin.qq.com/ → 右上角「**立即注册**」→ 账号类型选「**小程序**」
2. 填邮箱 → 设密码 → 去邮箱点激活链接
3. 主体类型选「**个人**」（⚠️ 选错无法修改，只能重新注册）
4. 填身份证号 + 手机号 → 管理员微信扫码验证
5. 注册完成后进后台 → **开发 → 开发管理 → 开发设置 → AppID**（复制它）
6. 补小程序基础信息：**名称**（想清楚再填，一年只能改 3 次）、头像、简介
7. **补充服务类目** → 选「**工具 → 信息查询**」，并设为**主营类目**

> 个人主体**不能**做：电商/外卖/收银/金融/教育/医疗类目。
> 本项目是纯查询统计，选「工具 → 信息查询」是最匹配也最容易被过的类目。

**拿到 AppID 后**告诉我，我立刻帮你：
- 填进 `miniprogram/project.config.json`
- 准备审核备注文案（写清数据来源、无支付无下单无诱导分享）
- 校验全部页面与合规项

## 路线二：正式上架微信（1～3 天）

### 步骤 0：前置准备

- [ ] 注册微信小程序账号：https://mp.weixin.qq.com/ → 立即注册 → **小程序**
- [ ] 完成**主体信息登记**（个人或企业）
- [ ] 拿到 **AppID**：登录后台 → 开发 → 开发管理 → 开发设置 → AppID
- [ ] 下载**微信开发者工具**（稳定版 Stable）：
      https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html

### 步骤 1：填入 AppID

编辑 `miniprogram/project.config.json`，把 `appid` 换成你的真实 AppID：

```json
"appid": "wx在此填入你的AppID",
```

> ⚠️ **别照抄示例里的占位符**。微信 AppID 的格式是 `wx` 开头 + 16 位十六进制字符，
> 如果你随手写一个符合这个格式的示例值，GitHub 的 Secret Scanning 会把它当成
> 真密钥报警（这是**误报**，但会一直发邮件提醒）。
> 用上面这种带中文的占位符就不会被扫出来。

> 现在填的是 `touristappid`（游客模式），只能预览不能上传。
> 如果你还没注册 AppID，**先别改**，用路线一就够了。

### 步骤 2：导入项目

1. 打开微信开发者工具 → 扫一扫登录
2. 点「**导入项目**」
3. 目录选 `mcd-flavor-index/miniprogram/` 这一层
   （注意：要选 `miniprogram` 目录本身，不是仓库根目录 —— 因为
   `project.config.json` 在这一层）
4. AppID 选你自己的（或者先用测试号）
5. 后端服务选「**不使用云服务**」——本项目数据全在本地，不需要云开发
6. 点「导入」

### 步骤 3：本地自测（重点测这几个）

| 测什么 | 怎么测 | 期望 |
|---|---|---|
| 真香榜渲染 | 首页应看到 9 个商品卡 + 官方图 | 图片全部显示，无破图 |
| 展开详情 | 点任意商品卡 | 看到官方标签 ↔ 真实共识、评分离散度条、投票区 |
| 广场发帖 | 广场顶部选商品 + 投票 + 写理由 → 发到广场 | 提示「已发到麦门广场」，我的投稿置顶 |
| 广场分组 | 往下滚 | 9 个商品分组，共 49 条评价 |
| 我的 Tab | 切到「我的」 | 能看到刚投过的票 |
| 筛选 | 广场点「真香」「踩雷」 | 列表正确过滤 |

> 开发者工具里如果报 `urlCheck` 相关错误，在详情 → 本地设置里
> **勾选「不校验合法域名」**（本项目只读本地 JSON，不请求外部域名）。

### 步骤 4：上传代码

1. 开发者工具右上角 → 点「**上传**」（不是「预览」）
2. 填版本号：`1.0.0`
3. 填项目备注：`麦门真香榜 · 官方标签 vs 真实口碑对账器（麦当劳 MCP 创意开发大赛参赛作品）`
4. 上传后，后台「版本管理」里会出现一个**开发版本**

### 步骤 5：提交审核

1. 微信公众平台 → 管理 → 版本管理 → 找到刚上传的开发版本 → 点「**提交审核**」
2. 填写审核信息：
   - **服务类目**：选「**工具 → 信息查询**」或「工具 → 数据统计」
     （本项目是查询/统计类，不要选电商或美食类的经营性类目，容易被驳回）
   - **功能页面**：把 4 个页面都选上（真香榜 / 详情 / 麦门广场 / 我的）
   - **测试账号**：本项目无需登录，如被要求可留空
   - **备注**：写清楚数据来源，例如：

     > 本项目为麦当劳程序员创意开发大赛参赛作品，数据来自：
     > 1) 麦当劳中国官方 MCP 接口（菜单/风味标签/核价）
     > 2) 49 篇公开用户评价（小红书/什么值得买/大众点评等，已标注来源）
     > 3) 所有投票与投稿仅存本地，不上传服务器
     > 不收集任何用户个人信息，无诱导分享、无支付、无下单功能。

3. 类目选「信息查询」+ 备注写清「无支付无下单」+ 页面里确实没有诱导分享
   —— 这三点是个人主体小程序审核通过的关键。

### 步骤 6：发布

审核通过后：
1. 后台「版本管理」→ 找到已通过审核的版本 → 点「**发布**」
2. 小程序就正式上线了，搜「麦门真香榜」或扫体验版码都能找到

### 步骤 7（可选）：提交信息获取 WorkBuddy 专项积分

官方规则：**排行榜前 100 名作品，提交 `workbuddy.md` 即可获得 3,000 WorkBuddy 积分**。
本仓库已包含 `workbuddy.md`，无需额外操作。

## 已知注意事项

### 包体
当前包体 **864KB**（上限 2MB），余量充足。
已清理掉 8 张与 `cdn-*` 内容完全重复的旧命名图（`food-*.png`），省下 620KB。

### 数据是预置的，不是实时接口
小程序包内带的是 `data/flavor.json`（9 个商品 / 49 篇评价 / 115 个在售快照）。
小程序**不直连麦当劳 MCP**（微信小程序不能带 Bearer Token 调外部接口，
且 MCP 端未必开放小程序来源）。

**官方数据更新靠定时任务刷新仓库 → 重新上传小程序**，
而不是小程序自己拉接口。这是有意的设计：避免在客户端暴露 Token。

### 名称
「麦门」是「麦当劳」的谐音梗。项目名 `麦门真香榜`，
类目和备注里建议注明「非麦当劳官方产品」——官方对此有明确要求。
