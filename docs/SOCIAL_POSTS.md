## 三、技术社区（掘金 / CSDN / 知乎 / V2EX）

**标题**：用麦当劳 MCP 做了个「官方标签 vs 真实口碑」对账器，发现了标签造假的代价

**正文要点**
1. **问题**：麦当劳 MCP 的 `query-meals` 会给每个商品打官方风味标签。
   但标签是营销语言，不是消费者语言。这两者之间的裂缝，没人量过。
2. **做法**：拉 115 个在售商品的官方标签 + 配料 + 套餐结构 + 核价（全走 MCP 接口），
   再采集 49 篇公开评价（小红书 / 什么值得买 / 大众点评 / 公众号 / 今日头条 / 现食研…），
   算出真香指数（均分）、评分离散度（最高星−最低星）、官方标签落差（标签声称的效果是否被评价否定）。
3. **最有意思的发现**：龙焰芝士棒鸡腿堡官方标签写「浓郁奶香拉丝芝士」，
   但 6 篇评价里 5★ 和 2★ 并存，离散度 3.0 全榜最高。
   另有 300+ 人大争论不素之霸的「58% 高蛋白」到底是福音还是陷阱。
4. **技术要点**：
   - MCP 返回的 `image` 字段会缺，需要三级降级（本地图 → CDN → 占位）
   - `calculate-price` 返回 0 且 `productList` 为空 ≠ 免费，是「不能脱离套餐单点」
   - `rounds` 比活动文案的官方介绍覆盖面大得多（实测 53 个套餐类商品有结构说明）
   - 菜单编码每日轮换，绝不能硬编码 productCode
5. **可玩**：https://zmz-beijita.github.io/mcd-flavor-index/（免 Token）

## 五、私信 / 评论回复模板（被问到时用）

**「这数据靠谱吗？」**
数据全部来自公开渠道，每条评价都标了来源平台，你可以点进 `data_ugc.json` 逐条核对。
评分是各平台原生评分按公开规则归一到 5 分制档位，映射表写在
`skills/mcd-flavor-index/references/ugc-collection.md`，不做黑箱。
样本量小是已知局限（49 篇 / 9 个商品），页面上 n 值、评分区间都一起显示了。

**「这不就是个点评网站？」**
点评网站给的是「这家店好不好吃」，这个给的是「官方宣传和真实口碑差多少」。
数据源是麦当劳自己的 MCP 接口 + 公开评价，官方标签每日自动更新、可溯源、不会过期。

**「能下单吗？」**
能，但不是主打。真香榜每张卡点开有官方配料清单和套餐结构，
人气榜有 115 个在售商品的官方核价——是「先看清再点」，不是「替你点」。
