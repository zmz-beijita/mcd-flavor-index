> 仓库：https://github.com/zmz-beijita/mcd-flavor-index

## 一个被所有人忽略的裂缝

麦当劳中国开放了官方 MCP（`mcp.mcd.cn`），其中 `query-meals` 会给每个在售商品打上**官方风味标签**。

```
龙焰芝士棒鸡腿堡 → ["浓郁奶香拉丝芝士", "韩式辣椒黄油风味", "上新"]
```

这些标签是麦当劳自己写的营销语言。问题在于：**营销语言和消费者语言之间，往往有一道裂缝。**

我去查了这个商品的真实公开评价，6 篇里 5 星和 2 星同时存在：

> 「大块原切鸡腿排……芝士棒外壳炸得金黄酥脆，趁热咬开，里面的马苏里拉慢慢涌出来」— 微信公众号测评，5★
>
> 「宣传图的拉丝完全是诈骗来的，实物根本没有拉丝，甚至第一口咬下去，**芝士棒是空心的只有面粉皮子**」— 微信公众号测评，2★
>
> 「两根没有奶酪的芝士棒在麦当劳值三块钱」— 今日头条，3★

官方说「浓郁奶香拉丝芝士」，真实用户说「芝士棒是空心的」。

**这道裂缝没人量过。我做了个工具把它量出来。**

## 它做了什么

### 三个指标

| 指标 | 算法 | 说明 |
|---|---|---|
| **真香指数** | 该商品全部真实评价评分的算术平均 | 5 分制 |
| **评分离散度** | 最高星 − 最低星 | 越大说明口碑越分裂 |
| **官方标签落差** | 官方标签声称的效果，是否被真实评价中的否定表述命中 | 关键词规则公开，不做黑箱 |

### 全量官方数据（全部走 MCP 接口）

- **115 个在售商品**：官方风味标签、配料清单、套餐结构、官方核价
- **66 种官方风味标签**（菜单每日轮换，实时拉取）
- **160 条营养数据**（副维度：钠 / 蛋白 / 热量）

### 49 篇真实公开评价

来自小红书 / 什么值得买 / 大众点评 / 微信公众号 / 今日头条 / 现食研 / 新厨房 / 携程点评 / 新浪看点 / 搜狐美食，**每条标注来源，差评也必须给出**。

## 三个有意思的发现

**1. 均分会骗人**

龙焰芝士棒鸡腿堡均分 3.7，看起来"中等"。但它的**评分离散度 3.0（满分 3），全榜最高**——有人狂赞，有人骂诈骗。只看均分就完全看不出这商品有多分裂。

**2. 一个新品，300+ 人在吵**

不素之霸双层牛堡，官方标签是「100%纯牛肉」「人气」。但在什么值得买，一条 4 星高蛋白分析能引出一大波人反驳"58% 高蛋白"是话术，真实差评直指高油高钠。真香指数 3.2，全榜倒数第二。

**3. 官方介绍覆盖率从 8/76 提到 58/115**

一开始我只用活动文案（`campaign-calendar`）找官方描述，覆盖率只有 8/76。换成读 `query-meal-detail` 的 **`rounds`**（麦当劳官方对"这个套餐由哪几部分组成、每部分能换什么"的说明）之后，覆盖率跳到 58/115。这个字段文档里不显眼，但信息量最大。

## 技术上踩的坑（8 条，详见 `MCP_INTEGRATION.md`）

几条关键的：

- **核价返回 0 不等于免费**。`calculate-price` 返回 `price: 0` 且 `productList` 为空，实际含义是"该商品无法脱离套餐单独点"。如果直接当 0 元用，页面会算出荒谬的套餐总价。
- **`query-meals` 的 meals 里没有 `name` 字段**，只有 `code` 和 `tags`。商品名得从 `query-meal-detail` 拿。
- **菜单编码每日轮换**，凌晨切早餐、上午切正餐。绝不能硬编码 `productCode`，必须每次实时拉菜单。
- **图片会缺**。115 个商品里接口只给 114 个有图。得做三级降级：本地已下载 → 远程 CDN → 分类占位图。
- **`searchType` 必须传 2**，默认 1 会返回"收藏餐厅列表为空"。

## 为什么不是"又一个点餐助手"

| | 点餐助手 | 麦门真香榜 |
|---|---|---|
| 回答的问题 | 怎么点最省 | **官方说的和实际差多少** |
| 数据来源 | 菜单 + 券 | 菜单**官方标签** + **真实评价原文** |
| 是否需要消费记录 | 需要 | 不需要 |
| 产物 | 一个订单 | **可核查的口碑审计 + 可下单的方案** |

同赛道已有 `mcd-flavor-scout`（手工标 119 款口味）和 `mcd-mood-palette`（心情 × 营养打分）。
两者的口味数据都是**手工标注**的，不可溯源、不会更新。

本项目的官方标签**直接来自 MCP 接口、每日自动更新**，并且多做一件没人做的事——**「官方 vs 真实」这道对账**。

## 诚实说明边界

- 样本量小是已知局限：49 篇 / 9 个商品，页面上 n 值和评分区间都一并显示
- 评分是各平台原生评分按**公开规则**归一到 5 分制档位，映射表在 `references/ugc-collection.md`
- 不是随机样本：采到的是能被检索到的公开评价，存在可见性偏差
- 平台偏差本身也是数据：小红书对新品更敏感，评分天然更两极

**这个项目的地基是 `data_ugc.json`** —— 纯文本、可 diff、可 review。任何人拿到它都能算出同样的真香指数。
